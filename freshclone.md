# Running Readest from a Fresh Clone

Everything needed to go from `git clone` to a running **web app** on a clean
machine. For desktop/mobile builds see the last section.

## TL;DR

```bash
git clone --recursive <repo-url> readest
cd readest

# Node 24 is required (see "Node" below)
nvm install 24 && nvm use 24

pnpm install
pnpm --filter @readest/readest-app setup-vendors

./web_app.sh start        # or: pnpm dev-web
# open http://localhost:3000
```

## Prerequisites

| Requirement | Why |
| --- | --- |
| **Git** with submodule support | The app imports five submodules directly (see below). |
| **Node 24** | The pinned toolchain. Node 18 (the usual system default) breaks install/build. There is no `.nvmrc`/`engines` field, so nothing stops you from using the wrong version — it just fails later. |
| **pnpm 11.1.1** | Pinned via `packageManager`; enable Corepack (`corepack enable`) and it is selected automatically. Do not use npm/yarn. |

## 1. Clone with submodules

The submodules are **hard dependencies**, not optional extras:

- `packages/foliate-js` — a workspace member; imported everywhere
  (`foliate-js/epubcfi.js`, `view.js`, …). `pnpm install` fails without it.
- `packages/simplecc-wasm` — mapped by `tsconfig` (`@simplecc/*` →
  `packages/simplecc-wasm/dist/web/*`). Its built `dist/` is committed, so no
  build step is needed.
- `packages/js-mdict` — mapped by `tsconfig` (`js-mdict` → `packages/js-mdict/src`).
- `packages/qcms` — PDF color management.
- `packages/tauri`, `apps/readest-app/src-tauri/plugins/tauri-plugin-turso`,
  `…/tauri-plugin-webview-upgrade` — only for desktop/mobile (Tauri) builds.

```bash
git clone --recursive <repo-url> readest
# already cloned without --recursive?
git submodule update --init --recursive
```

`--recursive` also fetches `apps/readest-app/.claude/skills/gstack`, a
third-party agent-skills repo that is **not needed to run the app**. If you want
to skip it (or it is slow/unreachable), initialize only what the web app needs:

```bash
git submodule update --init \
  packages/foliate-js packages/simplecc-wasm packages/js-mdict packages/qcms
```

## 2. Node and pnpm

```bash
nvm install 24 && nvm use 24     # or otherwise put Node 24 first on PATH
node -v                          # v24.x
corepack enable                  # activates pnpm@11.1.1 from packageManager
```

`web_app.sh` also activates Node 24 itself via nvm (override with
`NODE_VERSION=...`), but `pnpm install` run by hand does not.

## 3. Install dependencies

```bash
pnpm install
```

The root `prepare` script runs Husky (git hooks). No other postinstall is
required for the web app.

## 4. Vendor assets (`setup-vendors`)

`apps/readest-app/public/vendor/**` is **not committed** (ignored by
`apps/readest-app/.gitignore`) and is generated from the `foliate-js` submodule:

```bash
pnpm --filter @readest/readest-app setup-vendors
```

This copies the PDF.js worker, WASM and font/cmap files into
`public/vendor/pdfjs`. Without it the app still **starts** (the bundler resolves
PDF.js from `packages/foliate-js/node_modules`), but PDF reading will fail at
runtime, so run it as part of setup.

## 5. Run the web app

```bash
./web_app.sh start        # background dev server, port 3000
./web_app.sh status
./web_app.sh stop

# or foreground
pnpm dev-web
```

- URL: `http://localhost:3000` (change with `PORT=3001 ./web_app.sh start`).
- Logs: `.web_app.log`; PID: `.web_app.pid` (both git-ignored).
- The first `next dev` compile is slow (tens of seconds). A "Slow filesystem"
  warning appears if the repo lives on a network drive.

### Environment

`.env`, `.env.web` and `.env.tauri` are **tracked**, so the web dev environment
works out of the box. In web dev, `getAPIBaseUrl()` resolves to the same-origin
`/api` (the built-in Next route handlers), so local features such as the TTS
proxy (`/api/tts/openai`) work without extra configuration.

`.env.local` is optional and git-ignored; copy `apps/readest-app/.env.local.example`
only if you need to point the app at your own PostHog/Supabase/API endpoints.

## What is tracked vs generated

| Path | In git? | Notes |
| --- | --- | --- |
| `.env`, `.env.web`, `.env.tauri` | yes | dev/build environment |
| `pnpm-lock.yaml`, `Cargo*.lock` | yes | pinned dependency resolutions |
| `web_app.sh` | yes (executable) | background dev-server helper |
| `.gitmodules` + submodule trees | yes | must be initialized |
| `apps/readest-app/public/vendor/**` | **no** | run `setup-vendors` |
| `node_modules`, `.next`, `out` | **no** | generated by install/build |
| `.env*.local`, `.env.test.local` | **no** | optional local overrides |
| `.web_app.pid`, `.web_app.log` | **no** | runtime files |

## Common failures

- **`pnpm install` fails on a missing workspace package** → submodules are not
  initialized (`git submodule update --init --recursive`).
- **`next dev` fails resolving `foliate-js/...` or `@simplecc/...`** → same
  cause; the submodule trees are empty.
- **Cryptic errors / native build failures right after install** → wrong Node
  (v18). Put Node 24 first on `PATH`.
- **PDF pages blank / worker 404** → `setup-vendors` was not run.
- **First page takes ~a minute** → normal first Turbopack compile.

## Running tests (optional)

```bash
pnpm test                                  # full unit suite
pnpm lint                                  # tsc --noEmit && biome lint
```

`.env.test.local` is optional (dotenv-cli tolerates its absence).

Single-file runs are a documented gotcha: `pnpm test -- <file>` passes a literal
`--` and runs the **whole** suite. Use the explicit form:

```bash
pnpm --filter @readest/readest-app exec dotenv -e .env -e .env.test.local -- \
  vitest run src/__tests__/path/to/foo.test.ts
```

## Verification checklist

- [ ] `git submodule status` shows no leading `-` (all initialized).
- [ ] `node -v` is v24.
- [ ] `pnpm install` completes.
- [ ] `apps/readest-app/public/vendor/pdfjs` exists.
- [ ] `./web_app.sh start` prints "Readest web app started" and
      `curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3000/library`
      prints `200`.

## Other targets (brief)

- **Web production**: `pnpm build-web` then `pnpm start-web` (needs the API
  routes; for a self-contained server see `Dockerfile` / `docker/`).
- **Desktop (Tauri/AppImage)**: much heavier — Rust + the Linux CEF runtime,
  a `beforeBuildCommand` static export, and an AppImage-only `/api` gap (the
  desktop build has no local API routes, so server features fall back to
  `NEXT_PUBLIC_API_BASE_URL` or the default host). Not needed to run the web app.
